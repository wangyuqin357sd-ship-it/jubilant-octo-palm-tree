## 1. 一句话

**语忆是一个给视障学生的语音笔记工具：按一下录音，说一句「小语，结束」，
笔记就存好了，还能导出成能用手摸的中文盲文 —— 全程可以只用耳朵和手指。**

- 形态：单文件网页（`index.html`，390,028 字节，零依赖）+ 极薄的安卓外壳
- 语音助手叫「**小语**」
- 离线优先：识别在手机本地跑，录音**不出手机**

---

## 2. 痛点

### 2.1 三个真实的摩擦点

| 痛点 | 现实长什么样 | 代价 |
|---|---|---|
| **录了但用不上** | 录音笔里躺着 40 分钟音频。想找「第 3 章导数」那段，只能从头快进着听 | 整理成本 > 记录收益，于是干脆不用 |
| **整理必须靠眼睛** | 主流笔记 App 的「AI 总结」要你看着屏幕改错字、拖排序、点保存 | 视障学生被挡在门外 |
| **笔记不可触摸** | 中文盲文排版工具几乎都在 PC 上；手机端基本没有 | 「能摸的笔记」要另外找人转，链路断掉 |
| **一步一确认** | 很多 App 的语音只是「输入法」：录音、停止、保存、导出，每一步都要手指点 | 手忙/走路/拿东西时就废了 |

### 2.2 最要命的那一条：**误触发**

课堂上，同学咳嗽、老师说「结束」、隔壁聊天 —— 都可能让「语音停止录音」误触发。
**一次误触发的代价是一整节课的录音。**

所以我们把「结束录音」设计成**三步**：必须说完整唤醒词「**小语，结束**」→ 小语**出声反问你一次**
→ 你说「**是**」才真结束。宁可多问一句，也不要毁掉一节课。

## 3. 方案

### 3.1 核心流程（四步引导 + 三步确认）

```
  录音中                        ┌── ① 这段原音频归到哪个类目？
  说「小语，结束」               │      （说名字 → 小语复述 → 说「对」）
      │                         │
      ├─ ② 小语出声确认 ────────┤   ② 要不要做 AI 笔记总结？
      │   「要结束录音吗？        │      （要 → 离线转写 + 提炼要点/标签）
      │    已录 00:21。说『是』   │
      │    结束并保存；          ├── ③ 这条 AI 笔记归到哪个类目？
      │    说『不用』继续录。」    │
      │                         │
      └─ 说「是」→ 保存原音频 ────┴── ④ 要不要导出？
                                     ① 中文盲文 Word（默认）
                                     ② 盲文 BRF（点显器/盲文打印机）
                                     ③ 中文 Word
                                        → 文件落到手机「下载」
```

### 3.2 四个设计原则

1. **原声优先**：按下录音就开始存原始音频，**先保存音频，再决定要不要转写**。
   转写失败、断网、AI 报错，都**不会弄丢你的录音**。
2. **两条路走同一个状态机**：每一步都有「语音提问+语音回答」和「按钮」。
   你可以全程不说话，也可以全程不点屏幕。
3. **读屏状态 = 真实状态**：语音药丸不假装一直在监听；没配 AI Key 就明说「未配置」；
   识别失败就说失败。**不猜、不装。**
4. **失败必须可听见、可诊断**：说「**报告问题**」会把当前页面、状态、最近错误**全念出来** ——
   因为**盲人无法截屏**，这是远程求助的唯一通道。

## 4. 差异化

| 维度 | 常见做法 | 语忆的做法 |
|---|---|---|
| **语音的角色** | 语音 = 输入法（文字进去，流程还得手点） | 语音 = **完整控制通道**（能听、能答、能确认、能求助） |
| **识别在哪跑** | 云端（要联网、要上传、依赖厂商通道） | **手机本地 Vosk WASM**（不联网、不上传、不依赖通道） |
| **误触发防护** | 说「停止」就停 | **唤醒词 + 二次确认 + 已录时长播报**（课堂防误停） |
| **笔记的终点** | 文字列表 | **能摸的中文盲文**（Word / BRF 两种） |
| **AI 能力的位置** | 必须用厂商的（Key 藏在服务器） | **Key 是用户自己的**（18 家服务商预设，写在手机本地，可换、可清空） |
| **依赖** | 框架 + 构建工具 + 后端 | **一个 HTML 文件**，零依赖；构建只用三个压缩包 |
| **失败时的态度** | 静默失败 / 假装成功 | **出声说明失败原因**，并给可执行的下一步 |

### 4.1 「能摸的笔记」为什么重要

对盲人学生来说，**盲文不是怀旧，是唯一能「读第二遍」的形态**。
一份能导出成中文盲文 Word / BRF 的笔记，等于把「课后复习」这件事还给了他们。
实现上做到了**与后端 Python 逐字符等价**（同一份表、同一套查表顺序、同一套数字号/大写符/全角归一化规则），
验收 **217/217**，含全表 **44,388** 条聚合校验和一致。

## 5. 可以做什么（能力清单）

| 能做 | 细节 |
|---|---|
| ✅ 录音 / 暂停 / 继续 / 结束 | 结束带**三步防误停**；暂停与继续**刻意不做语音**（防误判） |
| ✅ 离线语音识别 | 手机本地 Vosk WASM，**不联网、不上传** |
| ✅ AI 笔记总结 | 可选；18 家服务商预设；总结与转写**可分别配不同服务商** |
| ✅ 自己起名的类目 | 「说名字 → 小语复述 → 说『对』」，长名字也认 |
| ✅ 原音频管理 | 播放 / 下载 / 重命名 / 删除；**原声永远保留** |
| ✅ 待办与提醒 | 语音 **5 步**录入；提醒走**振动 + 通知 + 语音播报（重复 2 遍）**三条通道 |
| ✅ 提醒出口 | 「知道了 / 停」、**「延后十分钟」**（语音优先于触摸） |
| ✅ 导出三种格式 | 中文盲文 Word / 盲文 BRF / 中文 Word；**APK 里真落到手机「下载」** |
| ✅ 不迷路的语音指令 | **我在哪 / 下一条 / 上一条 / 重试 / 报告问题** |
| ✅ 重复 / 试听 / 帮助 | 「重复」重念**当前提问**；「试听」是**振动+声音联合自检**（用来判断是音量问题还是马达问题） |
| ✅ 无障碍 | 双通道播报（polite/assertive）、44px 可点区域、`prefers-reduced-motion`、空态播报、失败可听见 |
| ❌ 自由闲聊 | **刻意不支持**：开放域对话会让误触发率飙升，而误触发的代价是一节课 |

## 7. 诚实边界

**任何对外材料都不应声称以下内容成立**（完整版见 [VERIFICATION.md §6](VERIFICATION.md#6-未验证清单)）：

| 边界 | 事实 |
|---|---|
| **云端识别在目标机型不可用** | 真机两次复现固定返回 `aborted`。**这正是改走离线识别的原因**，不是 bug |
| **短唤醒词模型精度有限** | 用 `vosk-model-small-cn-0.22`（小模型，面向短指令），长课堂录音**会有错字**；结果页如实标注 |
| **离线转写可能慢于实时** | **RTF ≈ 1.4–2.0**：10 分钟录音要等约 14–20 分钟 |
| **首次要等模型** | 41.9 MB 的 `model.tar.gz`，解包后约 65 MB；之后进 IndexedDB 缓存 |
| **部分机型需要装 TTS 引擎** | WebView **没有** `speechSynthesis`（真机自检实测），App 用原生 `TextToSpeech`；manifest 必须声明 `<queries> TTS_SERVICE`。**手机没有中文 TTS 引擎 → 小语是哑的** |
| **Word / 盲文无真实渲染校验** | 本机无 LibreOffice、WPS 无可用无头命令行 → **视觉观感未验证**（格式与内容已验） |
| **iOS / 微信浏览器未测** | 全部未测 |
| **未做真实用户端到端验证** | 各环节都验过，但**没有让真实盲人用户从开机走到导出**完整跑一遍 |
| **扬声器出声需人耳确认** | TTS 回调链走通，但「人耳确实听到」需人工确认 |
| **许可约束** | 中文盲文表派生自 Liblouis `zh-chn.ctb`（**LGPL-2.1-or-later**），**不受本项目 MIT 覆盖** |

## 8. 技术栈（一眼版）

```
单文件零依赖前端（390,028 B）
  ├─ 容错指令匹配（口语填充 / 谐音 / 最长命中优先）
  ├─ 零依赖 .docx 生成器（自写 ZIP + CRC32 + OPC）     137/137
  ├─ 中文盲文引擎（与 Python 逐字符等价）              217/217
  ├─ 双通道播报（aria-live）+ 真 TTS
  └─ localStorage + IndexedDB

离线语音识别：Vosk WASM（vosk-browser 0.0.8）+ vosk-model-small-cn-0.22   Apache-2.0

安卓外壳：极薄 WebView（assets 走 https://appassets.local 拦截）
  ├─ 原生 TextToSpeech（+ <queries> TTS_SERVICE）
  └─ 原生落盘（blob → base64 → MediaStore → 手机「下载」）

构建：无 Gradle / 无 Android Studio，9 步手工链，三个压缩包即可复现
```

一句话总结这个技术选择：**约束越硬，依赖要越少。**
视障用户的环境不可控（老手机、离线、被隔离的 WiFi），所以少一个依赖就少一种「打不开」。

## 9. 一页版（放 PPT 用）

> **语忆 —— 为视障学生做的离线语音笔记**
>
> - **痛点**：录了用不上、整理必须靠眼睛、笔记不可触摸、一步一确认、**误触发毁掉一节课**
> - **方案**：录音 → 说「小语，结束」（**三步防误停**）→ 四步引导（归类 / AI 总结 / 归类 / 导出）→ **能摸的盲文**
> - **差异**：语音是**完整控制通道**；识别**在本机离线跑**；导出**真中文盲文**；Key 是**用户自己的**；**一个 HTML 文件零依赖**
> - **实测**：主闸门 85/0 · docx 137/137 · 盲文 217/217（44,388 条校验和）· 离线识别 28/28 · APK 自检 15/15 · 真机 TTS 与导出均通
> - **诚实**：RTF 1.4–2.0（慢于实时）· 小模型有错字 · 部分机型需装 TTS 引擎 · Word/盲文观感未验 · iOS 未测
>
> **设计上唯一的硬约束**：语音和振动不可用的时候，这个产品就废了 —— 所以每个功能都必须有纯听觉+触觉的走法。
