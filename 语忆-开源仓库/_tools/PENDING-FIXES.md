## P0 · 底部 Tab「笔记」开的是弹窗而不是页面（用户实测反馈）

**现象**：点底部 Tab【笔记】弹出的是一个 modal sheet，不是切换页面；**关闭弹窗后底部 Tab 仍然亮在「笔记」**，而实际已经回到首页。

**为什么是 bug（不是"设计选择"）**：
1. **底部 Tab 是页面级导航**，语义上对应"切换整页"。用弹窗承载页面级导航，用户（尤其读屏/盲人用户）听到"笔记 当前页"，但屏幕上是个浮层——**位置感和层级感全乱**。
2. **Tab 高亮在撒谎**：关掉浮层后没有任何东西把它复位，`aria-current="page"` 仍指着「笔记」。对依赖读屏的盲人用户，这是在给错误的状态信息——**比不提示更糟**。

**要改成什么样（用户已确认交互）**：

**范围：底部 Tab 的落点全部改成全屏页面，一个都不许是浮层。**

| 底部 Tab | 全屏页 |
|---|---|
| 首页 | 语音药丸 + 大录音按钮（现状已是全页） |
| **笔记** | **全屏页：顶部两个按钮（原音频 / AI 总结笔记）用于切换，选哪个下面展示哪个的列表** |
| 待办 | 全屏页：振动提醒能力卡 + 通知开关 + 待办列表（现为浮层，需升级） |
| 我的 | 设置全屏页（现状已是全页） |

- 「AI」Tab **取消**（小语是助手，不占页面位置）；唤起方式 = 说「小语」/ 点首页药丸 / 任意页面的悬浮呼叫按钮。**待用户点头**（若保留则改成 5 Tab）。
- 「笔记」页的两个顶部按钮是**分段控件**：选「原音频」显示原音频列表，选「AI 总结笔记」显示笔记列表。
- **侧边栏【笔记】入口行为完全一致**（用户明确要求过两个入口一致）→ 同一个全屏笔记页。
- **中间那个「笔记 · 看哪一边？」确认弹窗取消**（它是浮层时代的补丁，分段控件取代它）。
- 原 `#audioPanel` / `#notesPanel` 两个浮层的内容搬进这个全屏页；其余浮层（目录 / 导出记录 / 接口配置 / 帮助）保留。
- **Tab 高亮只在真正处于该页时亮**；离开（返回/退出/语音跳走）必须复位到真实当前页。
- 验收：`aria-current="page"` 与"实际可见页面"必须始终一致 → **进闸门新增断言**。
- 无障碍补充（盲人用）：两个分段按钮要有 `role="tab"`/`aria-selected` 语义；**切换时播报**「已切到原音频，共 3 段」这类状态，让盲人知道当前在看哪一类、有多少条。

## P0-B · 小语的提问必须「说话」，不能只有文字（用户实测反馈）

**现象**：四步引导（① 归类 / ② AI 笔记总结 / ③ 笔记归类 / ④ 导出）以及「没听清」提示，**用户看到的是文字弹窗**。

**为什么是硬伤**：这些提示走的是 `alertSay()` —— 它**只往读屏的 live region 写文字**（aria-live）。若用户没开 TalkBack，**一声不响**；即使开了，那也是读屏在念，不是小语在说话。**盲人看不见弹窗、又没开读屏 = 完全不知道小语在问什么**，四步流程直接走不下去。

**要改成什么样**
- 所有小语的提问改用页面已有的 **`ttsSpeak()`**（真实 `speechSynthesis`）**真的出声**，并遵守「我的 → 朗读语速」的 `state.ttsRate`
- 覆盖范围（至少）：
  - ① 「这条原音频归到哪个大类？现有：高等数学、英语、课题。说类目名字，或说第一个。」
  - ② 「要对这条原音频做 AI 笔记总结吗？会先转成文字，再提炼要点。说需要或不用。」
  - ③ 「这条笔记放到哪个类目？现有：……，说类目名字，或说第一个。」
  - ④ 「要导出到本地吗？默认导盲文 Word。说需要就导它；想导普通中文文档说中文文档。」
  - 「我没听清，请再说一遍。」
  - 每页打开时的「你在哪 + 能做什么」（若做 P3）
- **避免和读屏重复朗读**：以 App 自己的 TTS 为主；live region 只在 **TTS 不可用或播放失败**时才写入同一段文字（否则 TalkBack 用户会听到小语和读屏各念一遍）。
- **说「重复」要能重念当前这条提问**（`ROUTES.repeat` 需要知道"当前问题"），这是盲人最基本的需求之一。
- **提问不能被其它播报打断**（例如 toast 触发的 `say()`）；需要保证问题完整念完。
- 验收：进闸门新增断言 —— 四步每一步都必须**真的调用过 `ttsSpeak`**（可用 `window.__yuyi` 暴露的调用记录/计数来断言，不能只看 aria-live 有没有文字）。

**依赖**：等要求 P0/P2 的整改代理交出 `index.html` 最终哈希后做，**单写者顺序执行，不与整改并行**。

## P4 · 离线识别收尾时暴露的三件小事（WASM 代理报告）

1. **数字口径**：`index.html` 的 toast 写「约 44 MB 中文模型」——模型本身 41.86 MiB 没错，但**首次总下载是 47.39 MiB**（引擎 5.53 + 模型 41.86）。文案应改成「首次约 47 MB」。
2. **`voiceSupported()` 判断太浅**：现在是 `!!(SR || window.YuyiASR)`，只表示**脚本加载出来了**，不代表环境可用。真正的环境自检是 **`YuyiASR.available()`**（查 WebAssembly / Worker / IndexedDB）。接线时应改用它，并确认 `init()` 失败 → `onError` → 降级路径走通（按钮/输入框照常可用，不弹红不卡死）。
3. **`model.tar.gz` 走 `no-store`**：每次刷新都会重新 `GET` 43 MB（worker 会把解包结果存 IndexedDB，第二次跳过解包但**下载仍发生**），且服务端 `_send()` 是整份读进内存再发。要决定是否给这个路径开缓存（`/data/asr/model.tar.gz` 加 `Cache-Control: max-age` + ETag）。

## P5 · ⚠️ 产品级风险：常驻监听可能跟不上（需实测 + 决策）

WASM 代理实测：本机负载下 wasm 稳态 **RTF 1.42–2.08**（同机 Python 原生也到 1.26–2.10，绝对值被负载污染，但可确定 wasm 约为原生的 1.2–1.5 倍开销）。后果：

**必须真机实测**，并按结果决定：① 常驻监听只做「唤醒词粗扫」；② 录音期间暂停常驻识别（已有 `rebindAsrToRecording` 复用麦克风）；③ 只在用户点了药丸后才常驻。**这是产品决定，需用户拍板。**

**另一个关键未测**：麦克风路径 `start({mic:true})`（getUserMedia + AudioWorklet）**只做了代码审阅、没实测**（headless 无麦克风）——真机上第一件要试的就是这条。

## P0-C · 全屏页去掉右上角的 ✕（用户实测反馈）

**现象**：底部 Tab 切出来的全屏页，右上角仍有一个 ✕ 关闭按钮 —— **看起来还是弹窗**。
**为什么必须去掉**：Tab 页面是"我在哪儿"，不是"临时浮层"。带 ✕ 会造成两个后果：① 读屏把它当对话框（`role="dialog"`/关闭按钮）念，盲人以为这是临时弹出；② 视觉与语义都在骗人，强化"浮层"心智模型。

**改成什么**
- 4 个全屏页（首页 / 笔记 / 待办 / 我的）**右上角的 ✕ 一律去掉**。
- "离开"= 切换底部 Tab（这就是页面导航该有的方式）。
- **必须保留可退出路径**：Tab 切换、语音「返回」/「回到首页」、ESC（回首页）。
- 去掉 ✕ 后要确认 **不能出现死代码**：原来靠 ✕ 走的 `closeScreen` 之类的逻辑若变成无入口，要么删掉、要么保证不产生错误状态。
- **验收（进闸门）**：去掉 ✕ 后，`aria-current="page"` 与"实际可见页"仍必须一致（P0 那条硬规则不能因为删按钮而破），且页面上**不存在**指向"关闭当前页"的按钮。

## P0-D · Tab 切换动画要流畅（用户反馈）

**现状**：4 个全屏页之间是 `hidden` 突变，没有过渡，观感生硬。
**改成什么**
- 加轻量过渡：`opacity` + `translateY(8px)` 之类，**140–200ms**，缓动自然。
- **只用 `transform` / `opacity`**，不用会触发 layout 的属性（手机性能）。
- **⚠️ 必须尊重 `prefers-reduced-motion: reduce`**：开启时**完全关掉动画**（前庭功能障碍/晕动症用户；这类用户里也有低视力者）。
- **不能牺牲无障碍**：过渡期间与结束后，`aria-current` 必须始终等于实际可见页；过渡结束后焦点落到新页的合理位置（页标题或首条内容）。
- **连点竞态**：必须断言"笔记→我的→笔记→首页"这种快速连点后最终状态正确（P0 代理已验过 49 条路径，加动画后要重验）。
- 验收：动画存在（有 transition 声明）+ reduced-motion 下为 none + 连点后 aria-current 正确。

- **必须复述确认**（识别任意人名/自定义名很容易错，盲人又看不到）：
  - 「新建类目"英语听力"。对吗？说"对"，或者说"重说"再讲一遍。」
- 支持的语音答法：类目名（新建或选中）、「第一个/第二个」选已有、「不归类」/「跳过」、「重说」、「取消」

- 类目名长度/非法字符要处理（空、纯标点、超长）→ 小语明说并请重说，不要静默吞掉
- **不预置任何类目**（数学/英语/课题全删）

**⚠️ 技术注意：类目名是「自由文本」，不能靠固定短语表匹配**
`MatchCmd` 是固定指令表；自定义类目名是无限集合。所以 ① 这步**必须把识别原文当"名字"处理**，不能走 `MatchCmd.match()` 的 null 分支被丢掉。
同时不能让别的场景也退化成自由文本——只在「① 正在等类目名」这个状态下才把原文当名字。
离线 Vosk 需用**自由听写模式**（phrase 表模式在这里不适用）。

### 🔴 P0-E 的连带硬问题：删掉演示数据后，**必须做持久化**，否则刷新一次全丢

- 上一条要如实写进界面与播报，不能只写在小字里

**未决定前不要仅删除假数据就交付**——那会造出"看起来好了、实际一刷新全空"的假象。

## P0-G · 「用户以为成功、其实失败」防御 + 标准指令（Lead 提出，用户 08:1x 拍板：**第 7 条不做，其余全做**）

> 设计原则：**盲人在不知情的情况下失败 = 最严重的缺陷**。下面每条的第一目标都是"让失败变得可听见"。

**按优先级执行：**

**1. 录音中途静默中断（最高优先）**
来电 / 别人抢麦 / 浏览器被系统冻结 / 息屏 → 录音断掉但界面无任何表现，用户**整节课白录且不知道**。
→ 监听 `MediaRecorder.onerror`、音轨 `onended`、`visibilitychange`；异常时**立刻出声**："录音中断了，已保存到「原音频」的有 X 分 Y 秒。"
→ 录音期间请求 `navigator.wakeLock` 防息屏；开始录音时出声道明"建议保持屏幕常亮"。

**2. 录音中的"心跳"**
录 20 分钟中间零反馈，用户不知道还在不在录。
→ **每分钟一次轻振动**（或极短提示音）；停止时播报总时长。

**3. 媒体音量/静音检测（性价比最高）**
媒体音量为 0 时 `speechSynthesis` 可能完全没声 → 用户以为"小语坏了/没反应"。
→ 开启语音时检测音量状态；为零则**振动 + 出声/提示**："你的媒体音量是 0，小语说话你听不见，请调大音量。"

**4. 存储写入失败必须出声**
IndexedDB 配额满 / 隐私模式 / localStorage 被禁 → 东西没存住，界面却正常。
→ 任何写入失败都出声说明，并明确"这条只在本次会话内有效"。

**5. 四句标准指令**
- 「**我在哪**」→ 念当前页 + 条数 + 可以说什么（迷路救命句）
- 「**下一条**」/「**上一条**」→ 列表内移动并念标题与摘要（盲人浏览列表的唯一途径）
- 「**重试**」→ 重做上一步失败的操作（转写/总结/导出/播报）
- 「**报告问题**」→ 念关键状态：识别引擎、麦克风、存储、最近错误、各列表条数。**盲人无法截屏，这是远程求助的唯一通道**

**6. 课堂防误停（会改变使用习惯，用户已同意）**
老师讲课出现含"结束"的话 → 录音停掉且用户无感。
→ 录音中**强制要求唤醒词**（「小语，结束」），命中后**二次确认**："要结束录音吗？说'是'。"

**8. 播放前播报来源**：正在播放第 N 条《…》。
**9. 朗读笔记时先念来源**："这条笔记来自 X 月 X 日的原音频，时长 12:40。"
**10. 大字号 + 长列表溢出**：`字号=特大` 配长列表未测，低视力用户会用，要验。
**11. 录音中刷新页面 = 丢录音**：录音期间提示，或做草稿恢复。

**~~7. 首次语音导览~~ → 用户明确不要，不做。**

**验收**：每条都要有"失败可听见"的断言——不能只断言正常路径。特别是 1/3/4：**要模拟失败**（断开音轨 / 音量置 0 / 写入抛错）并断言**确实出声了**（用 `window.__yuyi` 播报记录，不许只看文案）。

## P0-H · API Key 接入点：现在"形式可用、实质不可用"（用户 08:1x 要求修复）

**Lead 实测结论（不是猜）**：整条链路**功能正常**——入口行在、面板能开、18 个服务商预设、选预设自动填地址、保存写入 localStorage、「我的」行副标题同步更新、语音「打开接口配置」也能到、零 JS 错误。

**要做的（用户 08:2x 追加要求：只留一组，不要多个）**

**核心：合并成唯一一组配置。** 现在面板里有**两组**（① 总结用 / ② 转写用 = 2 个 Key + 2 个服务商 + 2 个地址 + 2 个模型，共 8 个框），用户明确说"**搞一个就可以了别搞多个**"。
- 只保留 **一组 4 个字段**：服务商 / 接口地址 / API Key / 模型
- **这套配置只用于「总结」（LLM）。转写默认走离线，不需要 Key** —— 用户 08:3x 指出："转写不是离线转写的吗？"
  - **转写 = 手机端离线 Vosk**（和语音指令同一个引擎+同一个模型）。零件已具备：`YuyiASR.decodeToPcm16k(录音Blob)` → 16k PCM → `YuyiASR.create()` + `feed(pcm)` → 文字。**不联网、不上传、不要 Key。**
  - 因此面板里**第二组（转写）整组删掉**，不是因为"嫌多"，而是**它本来就不该存在**。这也正好满足用户"只搞一个 Key"。
  - 可选升级（**默认关**）：若用户配的服务商支持转写，允许"用云端转写"作为**显式开关**，默认仍是离线。**不要**因为配了 Key 就偷偷走云端。
  - ⚠️ **必须诚实预告离线转写的代价**（实测 RTF 1.42–2.08，本机负载下就慢于实时；手机可能更慢）：开始前出声说"正在离线转写，可能需要 X 分钟"，允许**中止**，长录音要**分块喂 PCM**（45 分钟音频的 16k/16bit PCM ≈ 86 MB，不能整段进内存）。
